# BitGenesis V0 验收入口

现在可以验收一个能运行、回放、检查谱系和复现实验的最小达尔文世界。
**只有 V0 有运行代码**：个体、能量、遗传和繁殖是人为定义的，基因只控制随机移动概率。
食物感知、记忆和神经控制器仍未实现。

## 先打开哪里

下载[十七轮验收草稿](https://github.com/nikolasandwich/bitgenesis/releases/tag/untagged-817afa7dc5fa0391cfcc)，
完整解压 `bitgenesis-v0-seventeen-campaigns.zip`，从 `START-HERE.txt` 开始，
再打开 `bitgenesis/data/review-v0-17.html`。
保留目录结构，页面中的世界回放、谱系与图表依赖相邻文件。
草稿尚未正式发布，需要有权限的 GitHub 账号查看。

归档约 106 MB，含 1,260 个文件，固定源码 `8e4cf89`，包含十七轮原始记录和 117 项测试。
上传后的大小和校验值与本地一致。解压后新建独立安装，117 项测试全部通过；
新跑千步演示的事件与指标和原演示逐字节一致。第十七轮的 40 个初始状态、
10 组配对种子与 400,040 行指标重新核对后，完整验证报告与归档版本相同。
这些检查不意味着所有实验都被重新运行，也不是断网安装保证。
整包校验值、详细记录与历史归档见[完整检查点](ACCEPTANCE.md)。

归档包含中性标签核对、运行失败状态修复、断点校验、来源标注修复及加强的记录核对。
部分事后分析仍需从 Markdown 报告查看。
**归档不会随 main 的后续提交自动更新。** 复查旧实验使用其保存版本，验收最新代码使用 main。
旧十五轮归档直接运行解压源码时的来源标注限制见[来源说明](../design/experiments.md#extracted-source-and-git-provenance)；本次归档已包含修正。

## 最值得看的三个结果

| 问题 | 目前的证据 | 解释边界 |
|---|---|---|
| 简单规则能否产生遗传变化与谱系更替？ | [第一轮](campaign-001.md)有出生、死亡、差异繁殖；有突变与无突变世界最终都只剩一个创始谱系。 | 创始谱系不是物种；谱系胜出不独立证明性状优越。 |
| 世界规则会不会改变结果？ | [固定性状与竞争](campaign-003.md)显示种群承载数量与直接竞争胜负不同；改变移动成本可改变胜负。[第十二轮](campaign-012.md)发现免除出生扣费仍不能消除储能低阈值组的早期灭绝。 | 结果依赖当前规则、参数和有限种子，不能推出普适最优策略或唯一致死机制。 |
| 活得久、变化多，是否已经接近智能？ | [第十一轮](campaign-011.md)17 个世界活到十万步；[第十三轮](campaign-013.md)有突变组累计出现 340–371 种移动概率。 | 仍没有新的感觉、记忆或行动功能；有限时存活不是永久稳定，新增数值不是开放式创新。 |

最新[性状变化分解](trait-change.md)还说明：五个有突变世界全程均值上升，但直接突变项
累计为负；末一千步却有三个下降、两个上升。无突变世界末期性状固定，仍大量出生和死亡。
这是已有轨迹的精确记账，不能把某一项当作关闭突变的因果效果。

新增的[第十五轮](campaign-015.md)复查了四个暂时保留两组中性标签的世界：
全部在第 3,625—4,765 步间失去一组，剩余组存活到第 30,000 步。
这是条件选择的旧世界复查，不能用作稳定共存率或新独立样本。
该轮报告和运行失败状态修复已进入十五轮归档；十四轮及更早归档保持原范围。

最近追加的个体观测已整理为[机制分析简报](mechanism-summary.zh-CN.md)：区分摄食、出生空位和移动受阻，说明哪些解释仍未确定。这些后续观测不在固定十七轮下载包中。已另行提供[约 14 MB 的观测补充包](https://github.com/nikolasandwich/bitgenesis/releases/tag/untagged-b86474d93a9aef685e01)，需要有权限的 GitHub 账号查看草稿。解压后五项分析均已复算一致，使用方式见[补充包指南](../design/observation-supplement.md)。

## 怎样动手验收

1. 在回放拖动时间轴、切换基因与谱系着色，观察资源和种群变化。
2. 在归档的演示谱系页查询个体 1640，查看父代 1618、创始祖先 24 和直接子代记录。
3. 阅读图表旁的对照与局限，再按主 README 生成一个新实验并运行 `bitgenesis audit`。
4. 如需长时间运行，按[断点指南](../design/checkpoints.md)保存并继续世界状态。
   断点恢复不续写旧回放或指标 CSV；需要保持兼容的引擎源码与 Python 主次版本。

十七轮归档源码 `8e4cf89` 的 117 项测试在 Windows/Linux × Python 3.12/3.13/3.14
六种组合通过（[CI 34808083099](https://github.com/nikolasandwich/bitgenesis/actions/runs/34808083099)）。
测试覆盖能量收支、空间约束、遗传、记录核对和精确恢复等契约；通过测试不证明生物学真实性。
冻结重放只对已检查的运行与环境提供证据，不保证所有版本任意运行都逐位一致。

## 研究范围与继续方向

目前十八轮共 **864 次执行、7,840,000 个计算时间步**。其中 24 次是既有世界延长复查，
包含 212,000 步前缀重放，不是新增独立种子；事后分析也不增加实验数。
[第十六轮](campaign-016.md)已进入本次归档，比较等总量食物的不同空间分布。
最新[第十七轮](campaign-017.md)已核对：提高繁殖阈值后，两种布局的 20 个世界都存活到万步；它已进入本次归档。
所有协议、对照、灭绝结果和逐种子表格见[研究索引](README.md)。

当前倾向是保留 V0 作为可复现基线，继续解释机制与验证工具，再决定如何检验 V1 的感知能力。
[V1 设计](../design/v1-proposal.md)与[实验方案](../design/v1-experiment-design.md)已经写明
祖先、随机控制器和感官屏蔽对照，但尚未实现。单纯增加网络规模不会证明涌现。
阶段标准见[路线图](../roadmap/README.md)，逐项证据见[V0 验收对照](../roadmap/v0-evidence.md)，
过程记录见[研究日志](LOG.md)。

需要重新构建验收材料时，使用 `python scripts/build_v0_review.py --campaigns 17 --output data/my-review.html`；
需要完整本地数据，输出路径必须是新路径。打包方式和检查范围见[归档核验指南](../design/review-verification.md)。
